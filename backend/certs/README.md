# Корневой удостоверяющий центр для elk.roszdravnadzor.gov.ru

`russian-trusted-ca.pem` — корневой и промежуточный сертификаты
«Russian Trusted Root CA» и «Russian Trusted Sub CA» Минцифры России.

## Зачем

Государственный реестр медицинских изделий отдаёт публичный REST API на хосте
`elk.roszdravnadzor.gov.ru`. Его сертификат выдан национальным УЦ Минцифры,
которого нет в наборах доверенных корней ни у Node, ни у curl, ни у браузеров:
без этого файла загрузка падает с `unable to get local issuer certificate`.

Основной сайт `roszdravnadzor.gov.ru`, откуда берётся номенклатура, использует
обычный сертификат Let's Encrypt — для него этот файл не нужен.

## Как используется

Сертификат **добавляется** к доверенным для процесса API, проверка
сертификатов при этом не отключается:

```bash
NODE_EXTRA_CA_CERTS=./certs/russian-trusted-ca.pem node dist/main.js
```

Переменная действует только на этот процесс и не меняет доверие в системе.

## Происхождение и проверка

Файл скачан с официальной раздачи Минцифры:

- <https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt>
- <https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt>

Корневой сертификат самоподписан, действует с 01.03.2022 по 27.02.2032,
отпечаток SHA-256:

```
D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31
```

Проверить, что цепочка реального хоста подтверждается именно этим корнем:

```bash
curl --cacert certs/russian-trusted-ca.pem https://elk.roszdravnadzor.gov.ru/widget/
```

Команда должна вернуть 200 при включённой проверке сертификата.

## О чём помнить

Добавление корневого УЦ означает, что процесс будет доверять сертификатам,
выпущенным этим центром, для **любых** доменов, а не только для
`elk.roszdravnadzor.gov.ru`. Поэтому переменная задаётся только там, где
действительно нужна загрузка реестра, и не выносится в общий конфиг.
