# ADR 0009. Реальная интеграция с открытыми данными Росздравнадзора: номенклатура видов

- Дата: 2026-11-01
- Статус: принято
- Уточняет: [ADR 0008](0008-registry-provider.md)

## Контекст

ADR 0008 запрещал реализовывать реальный провайдер до появления официальной
документации и доступа. Проверка показала, какие источники существуют на самом
деле.

**Официального REST API у Росздравнадзора нет.** На
<https://roszdravnadzor.gov.ru/opendata> опубликованы файловые выгрузки:
28 публичных наборов в CSV и XML плюс реестр наборов
<https://roszdravnadzor.gov.ru/opendata/list.csv>. Слова «API» и «REST» на
странице не встречаются.

Наборы делятся на две группы, и разница принципиальна:

| Набор | Доступ |
| --- | --- |
| № 36 «Номенклатурная классификация медицинских изделий по видам в xml» | публично, без авторизации |
| № 11 «Государственный реестр медицинских изделий и организаций, осуществляющих производство и изготовление медицинских изделий» | только через авторизацию в ЕСИА на <https://gosuslugi.roszdravnadzor.gov.ru/opendata/> |

То есть именно регистрационные записи — те самые «РЗН 2024/21851», на которых
строится каталог — публично недоступны. Их выгрузка требует учётной записи
Госуслуг с правом на этот набор.

## Решение

1. **Номенклатура видов подключается как реальный источник.** Для набора № 36
   выполнены оба условия ADR 0008: есть официальная документация (XSD-схема
   `structure-20180615.xsd`) и открытый доступ без авторизации.

   - Файл данных: `data-ГГГГММДД-structure-20180615.zip` в каталоге набора
     `https://roszdravnadzor.gov.ru/opendata/7710537160-mi_types/`.
     Дата в имени — первое число месяца; на странице набора перечислены
     версии за предыдущие месяцы.
   - Адрес и имя файла задаются переменными окружения, а не зашиты в код:
     схема именования официально не описана, она выведена из перечня версий.
   - Провайдер `RoszdravnadzorNomenclatureProvider` сообщает о себе
     `isReal: true` — в отличие от демонстрационного.

2. **Реестр изделий остаётся за `MockRegistryProvider`.** Пока нет доступа к
   набору № 11, реальный провайдер регистрационных записей не создаётся:
   выдавать демонстрационные данные за государственный реестр нельзя
   (ADR 0008 в этой части сохраняет силу). `GET /government/sync` по-прежнему
   возвращает `source.isReal = false` для источника реестра, и теперь
   `isReal: true` для источника номенклатуры — состояния разных источников
   показываются раздельно.

3. **Загрузка потоковая.** Распакованный XML весит 52 МБ и содержит 33 032
   записи. Архив читается `yauzl`, XML — потоковым парсером `saxes`: документ
   целиком в память не попадает. Разбор по строкам не годится — в данных есть
   многострочные значения (13 описаний и 6 названий).

4. **Данные источника нормализуются при загрузке.** Структура файла и
   фактическое содержимое расходятся, поэтому модель строится по содержимому:

   - XSD объявляет `code` как `xs:int` и не запрещает повторы, и повторы в
     данных есть: 33 032 записи при 25 708 различных кодах. При этом
     **ни один код не встречается с разными названиями** — то есть запись XML
     описывает не «вид изделия», а пару «вид × путь раздела». Один вид может
     входить в несколько разделов: например, код 100260 «Система
     ультразвуковой костной денситометрии» встречается в путях `12/12.07`,
     `12/12.08/12.08.05` и `12/12.08/12.08.15`.
   - Поэтому виды и разделы хранятся отдельно, а их связь — в таблице
     `nomenclature_type_sections`. Код остаётся естественным ключом вида.
   - Путь раздела в файле приводится целиком (`12`, `12.08`, `12.08.05`), но
     в связь попадает только самый глубокий раздел: остальные выводятся
     обходом дерева по `parent_id`. Хранить весь путь означало бы хранить
     производное.

5. **Дефекты источника не роняют загрузку, а попадают в журнал.** В данных
   есть: 9 записей с пустым номером раздела, 76 пустых названий разделов,
   61 название, которое выглядит номером (например, раздел с номером `67` и
   названием `5.04` — поля явно перепутаны), 6 номеров с двумя вариантами
   названия и 9 — с двумя вариантами родителя, где один из вариантов пустой.

   Правила разбора: при расхождении выбирается непустое значение; запись с
   пустым номером раздела создаёт вид без привязки к разделу; каждый такой
   случай пишется в `sync_run_errors` со своим кодом, чтобы искажение
   источника было видно в журнале, а не молча исправлено.

## Последствия

- Плюс: каталог получает официальный классификатор из 25 708 видов вместо
  пяти демонстрационных категорий, с деревом из 591 раздела.
- Плюс: условие «не заявлять о реальном подключении, пока источник не
  подключён» соблюдается буквально — подключён ровно тот источник, который
  действительно доступен, и только он помечен как реальный.
- Минус: загрузка зависит от доступности сайта Росздравнадзора, поэтому в
  тестах и CI используется локальная фикстура, а обращение к сети включается
  отдельной переменной окружения.
- Минус: схема именования файла выведена из перечня версий, а не
  документирована. Если она изменится, потребуется правка переменной
  окружения, а не кода.
- Открытый вопрос: регистрационные записи реестра появятся только вместе с
  доступом к набору № 11 через ЕСИА.
