# ADR 0008. `RegistryProvider` с единственной mock-реализацией

- Дата: 2026-10-31
- Статус: принято
- Заменён в части реестра: [ADR 0010](0010-real-registry-integration.md) — реестр подключён как настоящий источник

## Контекст

Проект посвящён мониторингу государственного реестра медицинских изделий.
Официальной документации и доступа к API Росздравнадзора у проекта нет.

## Решение

1. Вводится интерфейс `RegistryProvider` (`src/sync/registry-provider.ts`) с
   методами выборки регистрационных записей и получения метаданных источника.
2. Единственная реализация — `MockRegistryProvider`. Она генерирует данные
   детерминированно из seed-набора и явно помечает себя
   `code = 'mock-registry'`, `isReal = false`.
3. Реальный HTTP-провайдер не создаётся. Заглушка, имитирующая ответы
   Росздравнадзора по угаданной схеме, не создаётся тоже.
4. API и UI обязаны показывать источник данных как демонстрационный:
   `GET /government/sync` возвращает `source.isReal = false`, а
   `POST /government/sync/run` в ответе помечает запуск как mock.
5. `sync_sources` содержит строку только для mock-источника. Строка с
   `base_url` официального реестра появится вместе с реальной интеграцией.

## Последствия

- Плюс: нигде в коде, API и интерфейсе не утверждается, что подключён реальный
  государственный источник.
- Плюс: точка расширения для реальной интеграции описана и изолирована.
- Минус: журнал загрузок на демо-данных показывает синтетические цифры; это
  явно помечено в ответе API.
