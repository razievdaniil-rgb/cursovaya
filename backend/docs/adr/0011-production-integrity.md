# ADR 0011. Целостность реестра и запуск без demo seed

- Дата: 2026-11-01
- Статус: принято
- Уточняет ADR 0010 в части идентификации, истории и завершения загрузки.

## Решение

1. Идентичность внешней записи задаёт внешний ID. Регистрационный номер
   остаётся альтернативным уникальным ключом; разные ID с одним номером —
   конфликт для журнала, а не основание молча объединить записи.
2. Частичный UNIQUE по источнику и `finished_at IS NULL` предотвращает
   параллельные загрузки несколькими процессами. Изменение изделия и истории
   выполняется под блокировкой строки одной транзакцией. Mock не меняет
   записи с внешним ID.
3. Производитель внешнего источника определяется точными именем и адресом,
   хешированными в отдельном пространстве UUID. Это не эвристическое
   объединение компаний по похожему названию. Изменение адреса создаст другую
   идентичность до появления официального идентификатора производителя.
4. Схема страницы валидируется. Отклонённые строки не исчезают из счётчиков,
   пустой после фильтрации список не обрывает обход. maxPages и изменение
   состава источника приводят к partial. Начальная история фиксирует время
   наблюдения текущего статуса, а не дату регистрации изделия.
5. HTTP-запуск возвращает 202 после сохранения run. Работа идёт в процессе API;
   это не отдельная долговечная очередь. Ошибка процесса оставляет явный
   незавершённый запуск для оператора. Порядок восстановления описан в operations.
6. Аналитические materialized views обновляются после импорта и раз в
   `ANALYTICS_REFRESH_INTERVAL_MINUTES` (по умолчанию 15). Производные величины
   не становятся источником истины.
7. Системные значения справочников входят в отдельную SQL-миграцию. Demo seed
   остаётся для разработки/тестов; production не получает тестовые пароли и
   изделия. Первого администратора создаёт оператор CLI-командой.

## Последствия

Схема остаётся реляционной в 3НФ: новая очередь и JSON-поля не вводятся,
инварианты защищены FK, UNIQUE и транзакциями. Появляются явные эксплуатационные
обязанности: HTTPS и email-провайдер в production, проверка живого работника
перед закрытием зависшего запуска, резервное копирование PostgreSQL.

Refresh rotation, сброс пароля и модерация отзывов также сериализованы
блокировками строк: повторные конкурентные запросы не создают второго
действительного токена или противоречащих друг другу событий истории.
